2. What Website CRM is

Website CRM is a lead management CRM. Authorized users sign in with Website CRM credentials. Lead and customer fields are primarily read from and written back to Google Sheets that an administrator connects for project use. Website CRM does not independently create a separate marketing lead database apart from those connected sheets and related operational records described below.

3. Information we process

Depending on how you use Website CRM, we may process:

  • Account information: name, login ID, role (Admin or Project User), account active status, and a password hash stored for authentication (passwords are not stored in plaintext).
  • Session and security information: web session identifiers, mobile session tokens (stored as irreversible hashes), CSRF tokens for browser requests, and session version values used to invalidate sessions.
  • Lead / customer information from connected Google Sheets: values present in authorized project sheets (for example name, phone, email, Lead Status, and other sheet columns configured for a project).
  • Operational CRM records: remarks and timeline/activity records associated with leads in authorized projects, including actor/author references for audit history.
  • Google authorization information (administrator Sheets connection): Google account identifiers (such as Google subject ID, email, name, picture URL) and an encrypted Google OAuth refresh token used only to access Sheets/Drive APIs for connected projects. Google OAuth is not the normal Website CRM login method. Administrators may disconnect Google authorization from the web Google Sheets connection screen. Disconnect removes stored Google credentials from Website CRM and does not delete Website CRM projects, remarks, timeline history, accounts, or Google Sheets/Drive files.
  • Project configuration: project names, spreadsheet identifiers, sheet titles, column metadata, and sync snapshot metadata needed to operate projects.

Website CRM does not include advertising SDKs, analytics SDKs, push-notification SDKs, or device-tracking SDKs based on the current application architecture. The mobile app stores an opaque session token in secure on-device storage for authentication.

4. Sources of information

  • Information you provide when an administrator creates your Website CRM account.
  • Information you enter while using the product (for example remarks or status updates).
  • Lead values synchronized from Google Sheets authorized by an administrator.
  • Google profile and OAuth token data when an administrator authorizes Sheets access.
  • Technical session metadata created when you authenticate.

5. How we use information

  • Authenticate users and enforce Admin / Project User authorization.
  • Display and update lead information for authorized projects.
  • Record remarks and timeline events for operational history.
  • Allow administrators to connect Google Sheets/Drive and manage projects and users.
  • Secure sessions, invalidate access after password or status changes, and support account deletion.

6. Storage and infrastructure

Application data is stored in the configured backend database (local SQLite in some development setups, or Turso/libSQL when configured for production). Google OAuth refresh tokens are stored encrypted at rest using server-side encryption keys. Lead field values remain in the connected Google Sheets; the CRM reads and updates those sheets through Google APIs.

7. Who can access information

  • Administrators may access authorized projects, user management, and Google connection status.
  • Project Users may access only projects assigned to them.
  • Service operators with access to the hosting environment and database credentials can access server-stored data as needed to operate the service.

8. Third-party services

  • Google APIs (Sheets and Drive): used to list spreadsheets, read sheet data, and update Lead Status values for connected projects. Google’s terms and privacy policy also apply to Google’s processing.
  • Database hosting (for example Turso): may store application records when configured by the operator.
  • Application hosting: the operator’s chosen host (for example a deployment platform) may process request traffic necessary to serve the application.

We do not sell personal information.

9. Security

We use industry-standard controls appropriate to this architecture, including password hashing (Argon2id), encrypted storage of Google refresh tokens, session authentication, CSRF protection for browser cookie sessions, bearer-token authentication for the mobile app, and role-based authorization. No method of transmission or storage is completely secure.

10. Retention

Account credentials and session data are retained while the account is active and as needed for security. After account deletion, Website CRM anonymizes the account record, removes project assignments, and invalidates sessions. Remarks and timeline history may remain for business audit continuity with de-identified author/actor display where applicable. Lead rows in Google Sheets remain under the control of the Google account and spreadsheet owners and are not deleted by Website CRM account deletion. Project and Sheets configuration are retained until an authorized administrator removes them or changes the connected sheets. Website CRM does not currently run separate automatic purge jobs beyond session/token expiry behavior.

11. Account deletion

Signed-in users may permanently delete their Website CRM account from the mobile app (More → Delete Account). Deletion is performed by the server after authentication and irreversibly de-identifies personal account fields (name, login ID, password hash), deactivates the account, removes that user’s project assignments, and invalidates sessions. Temporary freezing alone is not used as a substitute for deleting personal account data.

Users who cannot use the in-app flow may request deletion without reinstalling the app via the public page /delete-account (instructions and privacy/support contact). Public visitors cannot delete an arbitrary account from that page without operator identity verification.

The final remaining administrator account cannot be deleted until another administrator exists, to avoid locking the system. Account deletion does not delete Google Sheets, shared project lead rows, other users’ accounts, remarks/timeline business history, or the shared Google Sheets authorization used by Website CRM. Google authorization is a separate administrative connection (not bound to an individual CRM login). To remove Google credentials, an administrator should use Disconnect Google on the web Google Sheets connection screen.
